# Multilevel Number Indent

> ฉบับภาษาไทยของ [README](../README.md) · [ติดตั้งแบบละเอียด](INSTALL.th.md)

รายการหลายชั้นแบบที่คุ้นเคยใน Word แต่สร้างใหม่บนความจริงที่ว่าโน้ตหนึ่งไฟล์คือไฟล์ข้อความ

กด <kbd>Tab</kbd> รายการเลื่อนลึกลงหนึ่งชั้นพร้อมกับทุกอย่างที่อยู่ใต้มัน เลขทั้งหมดเป็น**ตัวอักษรจริงในไฟล์** ไม่ใช่การวาดทับด้วย stylesheet เลยติดไปกับข้อความได้ทุกที่ ทั้งตอนก๊อปปี้ ตอนส่งออก ตอนอยู่ใน git หรือตอนเปิดไฟล์ในโปรแกรม Markdown ตัวอื่น และเมื่อโครงร่างต้องออกจากโน้ต มันออกไปในสภาพที่ส่งต่อให้คนอื่นได้จริง ไม่ว่าจะเป็นข้อความล้วน รายการซ้อนที่เป็นรายการจริง หรือ rich text ที่เลขยังเป๊ะเหมือนที่เขียนไว้

![Multilevel Number Indent ใน Obsidian: 1. / 1.1. / 1.2.1. ลงไปถึง 1) และ 2.1)](../assets/demo.png)

## ทำไมต้องตัวนี้

| | |
|---|---|
| **รูปแบบเลขเป็นของคุณ** | `1.` `1.1.` `1)`, `a)`, `I.`, `ข้อ ๑.` หรืออะไรก็ตามที่ประกอบจาก placeholder ได้ ตัวอย่างผลลัพธ์จะเขียนใหม่ให้ดูสด ๆ ระหว่างพิมพ์ |
| **ลึกเท่าที่โน้ตต้องการ** | เพิ่มหรือลดจำนวนชั้นได้ตั้งแต่สองถึงสิบสอง ลึกเกินชั้นสุดท้ายจะเป็นอย่างไรก็เลือกได้ คือนับเลขต่อ หรือปล่อยให้บรรทัดนั้นเป็นเนื้อหาที่ยังรักษารอยเยื้องไว้ |
| **เข้าได้จากทุกที่ ออกได้ไปทุกที่** | วางรายการจาก Word หรือหน้าเว็บแล้วกลายเป็นเลขชุดนี้ให้ ส่งออกได้ทั้งข้อความล้วน rich text หรือรายการซ้อนที่แอปปลายทางเอาไปเรียงเลขเอง |
| **การย้ายรายการเป็นเรื่องหลัก** | <kbd>Alt</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd> สลับรายการกับพี่น้องชั้นเดียวกันพร้อมทั้งกิ่ง แล้วเคอร์เซอร์ยังอยู่ที่รายการเดิม ลากคลุมหลายรายการแล้วกด <kbd>Tab</kbd> ทั้งก้อนจะเลื่อนเข้าไปหนึ่งชั้นพร้อมกัน เรียงข้างกันเหมือนเดิม ไม่กลายเป็นขั้นบันได และยังเลือกค้างไว้ให้กดซ้ำได้ |
| **หัวข้อใช้เครื่องยนต์เดียวกัน** | `# 1 Introduction`, `## 1.1 Scope`, `#### 1) Point` เทมเพลตเดียวกัน กฎเดียวกัน นับใหม่อัตโนมัติเหมือนกัน |
| **อยู่ใน vault ของคุณ** | ไม่มีการเรียก network ไม่มี telemetry ไม่มี dependency ตอนรัน และไฟล์ที่ปล่อยไม่ผ่าน build step |
| **ตรวจที่มาของ release ได้** | ไฟล์ทุกตัวถูกเทียบไบต์ต่อไบต์กับไฟล์ใน repo และมี build provenance attestation |

## คีย์ที่ใช้

| คีย์ | บนบรรทัดเลข | บนบรรทัด heading |
|---|---|---|
| <kbd>Tab</kbd> | เลื่อนรายการและทั้งกิ่งเข้าไปหนึ่งชั้น | เพิ่มระดับ heading แล้วนับเลขใหม่ |
| <kbd>Shift</kbd>+<kbd>Tab</kbd> | ถอยรายการและทั้งกิ่งออกมาหนึ่งชั้น | ลดระดับ heading แล้วนับเลขใหม่ |
| <kbd>Enter</kbd> | เริ่มรายการถัดไปชั้นเดียวกัน | ปล่อยให้ Obsidian จัดการตามปกติ |
| <kbd>Alt</kbd>+<kbd>↑</kbd> / <kbd>↓</kbd> | สลับกับพี่น้อง**ชั้นเดียวกัน** | สลับทั้งหัวข้อกับ heading ชั้นเดียวกันที่อยู่ติดกัน |

การเลือกหลายบรรทัดจะย้ายเป็นกลุ่มเดียว ทุกรายการเก็บกิ่งของตัวเองไว้ครบ และเคอร์เซอร์อยู่ที่บรรทัดแรกของกลุ่ม

ทุกคีย์ทำงานเฉพาะบรรทัดที่ปลั๊กอินรู้จัก นอกนั้นไม่มีอะไรเกิดขึ้น <kbd>Tab</kbd> ยังเยื้องปกติของ Obsidian <kbd>Enter</kbd> ยังใช้ได้ในตาราง code block และเนื้อความ และ <kbd>Alt</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd> ไม่มีวันเปลี่ยนความลึก เคอร์เซอร์จะตามรายการไปทุกที่ที่มันลง

## รูปแบบเลข

ค่าเริ่มต้นหน้าตาแบบนี้

```text
1. บทนำ
  1.1. ขอบเขต
    1.1.1. รายละเอียด
      1) ข้อแรก
        1.1) ข้อย่อยของข้อแรก
      2) ข้อสอง
2. สรุป
```

ชั้น 1 ถึง 3 แสดงเต็มพาธและลงท้ายด้วยจุด `1.` `1.1.` `1.1.1.` ส่วนชั้น 4 ลงไปนับใหม่และลงท้ายด้วยวงเล็บ `1)` `1.1)` ทุกชั้นเยื้องด้วยสองช่องว่าง ข้อความจึงเลื่อนไปขวาครั้งละสี่คอลัมน์และตรงกันเป็นตารางเสมอ

ความลึกอ่านจากรอยเยื้อง ไม่เคยอ่านจากเลข นี่คือเหตุผลที่กด <kbd>Tab</kbd> แล้วมันเขียนเลขใหม่แทนที่จะแค่เลื่อนบรรทัด `1.1.1.` กลายเป็น `1)` เมื่อลงชั้น 4 และ `1)` กลับเป็น `1.1.2.` เมื่อขึ้นมา เคอร์เซอร์อยู่ในเนื้อหาเสมอ ไม่มีทางไปค้างอยู่กลางเลข

`1.1.` ตั้งใจไม่ให้เป็น list marker ของ Markdown นั่นคือเคล็ดทั้งหมด เพราะเลขเป็นข้อความล้วนมันจึงติดไปกับโน้ตด้วย ข้อยกเว้นเดียวคือ `1.` ที่ราก และ `styles.css` จะลบรอยเยื้องรายการของ Obsidian บนบรรทัดที่รู้จัก เพื่อให้ทุกชั้นอยู่ในตารางเดียวกัน

![โครงร่างเดียวกันในหกรูปแบบเลข](../assets/example.svg)

### Placeholder

| Placeholder | แสดงผล |
|---|---|
| `1` | `1` `2` `3` … |
| `a` / `A` | `a` `b` … / `A` `B` … |
| `i` / `I` | `i` `ii` `iii` … / `I` `II` `III` … |
| `ก` | `ก` `ข` `ค` … |
| `๑` | `๑` `๒` `๓` … |

นอกนั้นในเทมเพลตคือตัวอักษรธรรมดาที่คุณพิมพ์เอง เครื่องหมายคั่นและเครื่องหมายปิดจึงเป็นของคุณ สิ่งที่ placeholder กำหนดคือชั้นหนึ่งแสดงพาธกี่ช่วง หนึ่งตัวคือหนึ่งช่วง สามตัวคือเต็มพาธ นี่คือเหตุผลที่ค่าเริ่มต้นนับใหม่ที่ชั้น 4 ซึ่งแถวคือ `1)`

```text
1.1.1.     ->  1.1.1.         เต็มพาธ ปิดด้วยจุด
1)         ->  1)             หนึ่งช่วง เลขจึงนับใหม่
1.1)       ->  1.1)           สองช่วง
a)         ->  a) b) c)       ตัวอักษร
I.         ->  I. II. III.    เลขโรมัน
ข้อ ๑.     ->  ข้อ ๑.          คำนำหน้าตัวอักษรจริง
1.1(a)     ->  1.1(a)         แบบกฎหมาย
```

แถวที่ไม่มี placeholder จะถูกข้าม และชั้นนั้นคงค่าเดิมไว้ เปลี่ยนรูปแบบทีหลังก็ปลอดภัย เลขที่เขียนไว้ในรูปเก่ายังถูกจดจำ และ <kbd>Tab</kbd> ครั้งต่อไปจะเขียนใหม่เป็นรูปใหม่ให้

### จำนวนชั้น และสิ่งที่เกิดหลังชั้นสุดท้าย

ทุกแถวในรายการชั้นมีปุ่ม **Add level** และ **Remove** ส่วนบรรทัดที่ลึกเกินชั้นสุดท้ายจะเป็นอย่างไร เป็นคนละตัวเลือก ชื่อ **Deeper than the last level**

- **Reuse the last level** นับเลขต่อทุกความลึก ไม่ว่าโน้ตจะลึกแค่ไหน นี่คือค่าเริ่มต้น
- **Leave it as text** เก็บรอยเยื้องไว้แต่ตัดเลขออก เหมาะกับโน้ตที่เป็นของรายการใดรายการหนึ่ง ไม่ได้เป็นส่วนหนึ่งของโครงร่าง <kbd>Tab</kbd> จะหยุดที่ชั้นสุดท้ายแทนที่จะดันโน้ตพวกนั้นหลุดออกจากโครงร่าง

### รูปแบบรายโน้ต

โน้ตไหนก็พกรูปแบบเลขของตัวเองใน frontmatter ได้ ค่าทั่วไปจะกลับมาเองที่โน้ตถัดไป ไม่ต้องย้อนแก้อะไร

```yaml
---
numbering:
  indent: "\t"
  depth-policy: unnumbered
  formats:
    - "1."
    - "1.1."
---
```

`formats` เขียนบรรทัดเดียวก็ได้ `formats: ["a.", "a.a."]` ค่าที่ไม่ใช่เทมเพลตที่ถูกต้องจะถูกข้ามไป ไม่ใช่ถูกใช้แบบครึ่ง ๆ

### Preset

Preset คือรายการชั้นทั้งชุดที่บันทึกไว้ภายใต้ชื่อ มีมาให้หกชุด คือจุดแล้ววงเล็บ จุดเต็มพาธ ตัวอักษร เลขโรมัน แบบกฎหมาย และแบบไทย **Apply a preset** เอาชุดนั้นมาแทนรายการชั้น **Save the current list** บันทึกชุดที่คุณประกอบไว้ และถ้าบันทึกทับชื่อที่มีอยู่แล้วของคุณจะแทนที่ของเดิม

**Preset JSON** คือวิธีย้ายชุดที่บันทึกไประหว่างเครื่อง **Export** คัดลอกลง clipboard พร้อมใช้บนอีกเครื่อง **Import** อ่านจากกล่องข้อความแล้วแทนรายการที่บันทึกไว้ อะไรที่ไม่ใช่รายการ preset ที่สะอาดจะถูกปฏิเสธ ไม่ใช่ถูกนำเข้าแบบครึ่ง ๆ

## หน้าตั้งค่า

ทุกอย่างอยู่ในแท็บเดียว **Settings → Multilevel Number Indent**

![หน้าตั้งค่า: จำนวนชั้นเท่าที่โน้ตต้องการ และสิ่งที่เกิดหลังชั้นสุดท้าย](../assets/settings.png)

| หมวด | ข้างในมีอะไร |
|---|---|
| **Indent per level** | สองช่องว่าง สี่ช่องว่าง หรือหนึ่ง tab |
| **Deeper than the last level** | นับเลขต่อ หรือปล่อยบรรทัดเป็นเนื้อความ |
| **Format pasted lists** | แปลงรายการตอนกด <kbd>Ctrl</kbd>+<kbd>V</kbd> ปิดมาให้จากโรงงาน |
| **Indent guides** | เส้นจาง ๆ หนึ่งเส้นต่อหนึ่งรายการที่มีข้อย่อย วางใต้เลขหลักสุดท้ายของรายการนั้นพอดี แล้วลากลงไปจนถึงข้อย่อยตัวสุดท้าย ระหว่างเปิดไว้ เส้นไกด์ของ Obsidian เองจะหลบให้บนบรรทัดที่มีเลข |
| **Number format** | เทมเพลตหนึ่งรายการต่อชั้น พร้อมปุ่ม **Add level** กับ **Remove** และตัวอย่างแบบสด |
| **Presets** | มาให้หกชุด บันทึกชุดของตัวเองได้ และ **Preset JSON** สำหรับย้ายระหว่างเครื่อง |

## ข้อความที่พร้อมใช้

เลขเป็นแค่ครึ่งเดียวของงาน สิ่งที่สำคัญคือข้อความที่ออกมา

![ข้อความชุดเดียวสามสถานะ: วางมาจาก Word, ได้เลขในโน้ต, ออกเป็นข้อความล้วน](../assets/flow.svg)

| คำสั่ง | ทำอะไร |
|---|---|
| `Normalize the outline` | จับโน้ตที่เพี้ยนกลับเป็นทรงเดิม แล้วนับเลขใหม่จากความลึกจริง |
| `Turn the selection into a numbered outline` | แกะรายการที่วางเข้ามาแล้วสร้างใหม่ในเลขชุดนี้ ทั้ง bullet และเลขแปลกหน้า |
| `Copy as clean text` | เลือกส่วนที่เลือกเป็นเนื้อความ ลิงก์เหลือแค่ข้อความที่แสดง ตัวกำกับ callout คอมเมนต์ และการเน้นตัวอักษรหายหมด |
| `Save the selection as a clean note` | ข้อความล้วนชุดเดียวกัน เขียนลงโน้ตใหม่ |
| `Copy as formatted text` | HTML และ RTF ที่เลขยังเป๊ะเหมือนอ่านในโน้ต |
| `Copy as a real nested list` | HTML และ RTF เป็นรายการซ้อนจริง ให้ Word และแอปเมลเรียงเลขเอง |

**Format pasted lists** ในหน้าตั้งค่าทำแบบแรกให้อัตโนมัติตอนกด <kbd>Ctrl</kbd>+<kbd>V</kbd> ปิดมาให้จากโรงงาน และทำงานเฉพาะข้อความที่หน้าตาเป็นรายการจริง ๆ

### Smart placement

เวลาลิสต์มาจาก Word หน้าเว็บ หรือแชท ตัวเลขมักจะรู้ชั้นมากกว่าการเยื้อง ระบบจึงให้**ตัวเลขบอกชั้นเอง**: `1.1 ข้อความ` คือชั้น 2 และ `1.1.1 ข้อความ` คือชั้น 3 ไม่ว่าหน้าบรรทัดจะเยื้องมายังไง เฉพาะเลขแบบมีจุด (`1.1`, `1.1.1`, `1.1.1)`) เท่านั้นที่ได้สิทธิ์นี้ ส่วนบรรทัดที่ขึ้นต้นด้วย `1` เฉย ๆ ยังถือเป็นเนื้อความและวางชั้นจากการเยื้องเหมือนเดิม การเยื้องที่ไม่ตรงกันจึงผลักให้รายการตกชั้นไม่ได้ ลิสต์ที่เยื้องเพี้ยนก็ออกมาเป็นระเบียบเอง

ใช้ได้ทั้งสองทางเหมือนกัน: คำสั่ง `Turn the selection into a numbered outline` บนส่วนที่เลือก หรือ <kbd>Ctrl</kbd>+<kbd>V</kbd> ตอนเปิด **Format pasted lists** ไว้ คลิกขวาที่ข้อความก็เจอในเมนู **Multilevel list section** เหมือนกัน คือเลือกบรรทัด คลิกขวา เลือกคำสั่ง แล้วลิสต์จะจัดชั้นให้เองทั้งก้อน

ช่องว่างที่แคบที่สุดในข้อความจะบอกว่าหนึ่งชั้นกว้างเท่าไร ลิสต์ที่เยื้องด้วย 3 ช่องหรือ tab ก็ยังออกมาชั้นละขั้นตามปกติ และตัวเลขเป็นการนับใหม่เสมอ ไม่ใช่ลอกมา: `1.2.4` ที่เขียนใต้ `1.2.1` จะกลายเป็น `1.2.2` เพราะเลขนับตามชั้นจริงตลอด

## เลขบนหัวข้อ

หัวข้อใช้เทมเพลตชุดเดียวกันแต่ตัดจุดปิดท้าย `# 1 Introduction`, `## 1.1 Scope`, `### 1.1.1 Detail` ตั้งแต่ชั้น 4 เป็นต้นไปใช้กฎเดียวกับข้อความล้วนและลงท้ายด้วยวงเล็บ `#### 1) Point`, `##### 1.1) Detail`

การเปลี่ยนระดับหัวข้อหรือย้ายหัวข้อจะนับเลขใหม่ให้เอง แต่**เฉพาะเมื่อโน้ตอยู่ในโหมดมีเลข** คือมีหัวข้ออย่างน้อยหนึ่งตัวที่มีเลขแล้ว โน้ตที่ยังไม่มีเลขจะไม่ถูกแตะต้อง <kbd>Tab</kbd> จึงไม่มีวันเริ่มใส่เลขให้เอกสารโดยไม่ได้ตั้งใจ `Number headings in note` เปิดโหมดนี้ `Remove heading numbers` ปิด

ปกติหัวข้อจะเริ่มรายการชุดใหม่ รายการใต้หัวข้อนั้นจึงเริ่มนับจาก `1.` ใหม่ ถ้าอยากให้นับต่อเหมือน Word ที่ปล่อยให้รายการข้ามหัวข้อไปได้ คลิกขวาที่บรรทัดหัวข้อแล้วเลือก **Continue numbering past this heading** ส่วน **Restart numbering at this heading** กลับไปเริ่ม `1.` ตามเดิม ตัวเลือกนี้เก็บเป็น HTML comment บนบรรทัดหัวข้อ ทั้ง reading view และ `Copy as clean text` จึงไม่มีวันเห็นมัน

## คำสั่งทั้งหมด

| คำสั่ง | ทำอะไร |
|---|---|
| `Number headings in note` | เขียน `1` / `1.1` / `1.1.1` ลงทุกหัวข้อ |
| `Remove heading numbers` | ลบเลขออกจากทุกหัวข้อ |
| `Renumber multilevel block` | คำนวณเลขใหม่จากรอยเยื้องจริง |
| `Insert multilevel numbering` | เปลี่ยนโครงร่างที่เยื้องด้วยช่องว่างให้มีเลข |
| `Remove multilevel numbering` | ลบเลข เก็บรอยเยื้องไว้ |
| `Normalize the outline` | จับโครงร่างที่เพี้ยนกลับเป็นทรงเดิมแล้วนับเลขใหม่ |
| `Turn the selection into a numbered outline` | แปลง bullet และเลขแปลกหน้าตอนวาง |
| `Cut the item with its subtree` | ตัดรายการพร้อมทุกอย่างที่อยู่ใต้ เตรียมไปวาง |
| `Paste the cut item here` | วางกลับหลังรายการปัจจุบันในชั้นเดียวกัน |
| `Move the item to a level` | ถามว่าชั้นไหนแล้วย้ายรายการและกิ่งไป |
| `Continue numbering past this heading` | ปล่อยให้รายการนับต่อข้ามหัวข้อ แทนที่จะเริ่ม `1.` ใหม่ |
| `Restart numbering at this heading` | เริ่มนับ `1.` ใหม่ใต้หัวข้อนี้ |
| `Clear list markers and keep the indent` | ท่า clear format: ตัวเลขและ bullet ทุกแบบออกจากหน้าบรรทัด เลขออกจากหัวข้อด้วย แต่คงการเยื้องไว้เท่าเดิม |
| `Copy as clean text` | เลือกส่วนที่เลือกเป็นเนื้อความ ไม่มีตัวกำกับ Markdown |
| `Save the selection as a clean note` | แบบเดียวกัน เขียนลงโน้ตใหม่ |
| `Copy as formatted text` | Rich text ที่เลขยังอยู่ครบ |
| `Copy as a real nested list` | Rich text เป็นรายการซ้อน ให้ปลายทางเรียงเลขเอง |

ทุกคำสั่งเป็นหนึ่ง editor transaction ดังนั้นกด <kbd>Ctrl</kbd>+<kbd>Z</kbd> ครั้งเดียวได้ทุกอย่างกลับคืน

คลิกขวาในตัวแก้ไข แล้วคำสั่งทั้งหมดนี้ก็อยู่ใน **Multilevel list section** กลุ่มของตัวเองที่แยกออกมาชัดเจน แบ่งเป็นหมวดย่อยให้สี่หมวด คือ **Numbering**, **Moving items**, **Copying out** และ **Headings** สองคำสั่งสำหรับหัวข้ออยู่ในหมวด Headings และขึ้นมาให้เลือกเฉพาะตอนเคอร์เซอร์อยู่บนบรรทัดหัวข้อเท่านั้น

## ปลั๊กอินนี้แตะอะไรบ้าง

ไม่มีการเรียก network ไม่มี telemetry และไม่มีอะไรถูกโหลดตอนรันเพิ่มจากที่โฮสต์มีอยู่แล้ว แต่มีสองอย่างที่ควรบอกให้ชัด

- **Clipboard และเฉพาะตอนคุณสั่งเท่านั้น** `Copy as clean text`, `Copy as formatted text` และ `Copy as a real nested list` เขียนลงไป ส่วน `Format pasted lists` อ่านสิ่งที่คุณเพิ่งวาง ผ่าน paste event เอง ไม่มีการอ่านหรือเขียนอะไรในพื้นหลัง
- **โน้ตของคุณ ผ่าน vault API ปกติ** ทุกคำสั่งเป็นหนึ่ง editor transaction กด <kbd>Ctrl</kbd>+<kbd>Z</kbd> ครั้งเดียวคืนได้ทั้งหมด ไม่มีไฟล์ไหนถูกแตะนอกเหนือจากโน้ตที่คุณเปิดอยู่ ยกเว้น `Save the selection as a clean note` ที่สร้างโน้ตใหม่หนึ่งไฟล์ตามชื่อที่คุณตั้ง

## การติดตั้ง

**จาก community directory** **Settings → Community plugins → Browse → Multilevel Number Indent**

**ติดตั้งเอง** คัดลอก `main.js`, `manifest.json` และ `styles.css` ลงใน `<vault>/.obsidian/plugins/nested-outline-numbering/` แล้วเปิดใช้ใน **Settings → Community plugins** อ่านรายละเอียดเพิ่มที่ [INSTALL.th.md](INSTALL.th.md)

## การใช้ร่วมกับปลั๊กอินอื่น

ปลั๊กอินอื่นที่ผูก <kbd>Tab</kbd> ใน editor (อย่าง Obsidian Outliner) ไม่เป็นปัญหา เพราะตัวนี้ฟังที่ capture phase ของ `keydown` และหยุด event ก็ต่อเมื่อข้อความเปลี่ยนจริง ๆ Outliner จึงเยื้องรายการของมันต่อไป ส่วนบรรทัดมีเลขเป็นของปลั๊กอินนี้

สิ่งที่ไม่ควรทำคือปล่อยให้สองปลั๊กอินอ้างคีย์เดียวกันบนบรรทัดประเภทเดียวกัน ถ้ากำลังย้ายมาจากปลั๊กอินทำนองเดียวกัน ปิดตัวเก่าก่อน

## ภายในเป็นอย่างไร

`main.js` เป็นไฟล์ CommonJS เขียนมือไฟล์เดียว ไม่มี build step ไม่มี dependency ตอนรัน และไม่มีอะไรนอกเหนือจาก `obsidian` กับ `@codemirror/*` ที่โฮสต์มีให้อยู่แล้ว

แบ่งเป็นสองส่วนโดยตั้งใจ

- **CORE** คือการแปลงข้อความล้วน (`indentItem`, `outdentItem`, `newSibling`, `moveItem`, `normalizeOutline`, `ingestOutline`, `cleanForExport`, `buildHtmlOutline`, `cutItem`, `pasteItem`, `setLevel`, `shiftHeadingLevel`, `moveHeading`, `numberHeadings`, …) ไม่แตะ Obsidian API เลย นี่คือเหตุผลที่มันทดสอบนอกแอปได้
- **PLUGIN** คือคลาส `Plugin` ที่ต่อคีย์และคำสั่งเข้ากับ core แล้วส่งผลลัพธ์เป็น editor transaction เล็กสุดทีละครั้ง

## การพัฒนา

```bash
npm ci
npm run build
```

ไฟล์เทสต์ stub `require("obsidian")` และ `require("@codemirror/*")` เพื่อให้ `main.js` โหลดใน Node ธรรมดาได้ แล้วรัน 292 ข้อความกับ core ครอบคลุมการนับเลข การย้ายทั้งกิ่ง ตำแหน่งเคอร์เซอร์ code fence ตัวนับ heading เทมเพลตเลขและรอบไปกลับ เลขไทย ตั้งค่าจำนวนชั้นและนโยบายความลึก preset และ JSON ของมัน frontmatter รายโน้ต normalize วางแบบฉลาด ข้อความล้วน ผลลัพธ์ HTML และ RTF การย้ายหลายบรรทัด การตัดและวางเป็นกิ่ง indent guides และ status bar

นอกจากนั้นยังสร้างหน้าตั้งค่ากับ double ตัวเล็ก ๆ ของ `Setting`, `PluginSettingTab`, `Modal` และ container element เพื่อตรวจแถว ปุ่ม ตัวอย่าง และการตรวจสอบค่า บล็อกแรกของชุดเทสต์ตรวจโครงร่างที่ตัวโหลดของ Obsidian ต้องการ (`module.exports`, `.default`, `prototype.onload`) เพื่อไม่ให้ export ที่เสียหลุดรอดไปได้

ไม่มีขั้นตอนคอมไพล์ `npm run build` แค่รันชุดเทสต์นี้ ซึ่งเป็นวิธีที่ build-verification ยืนยันว่า `main.js` ใน repo ทำได้จริงตามที่ README นี้บอก

## ข้อจำกัดที่รู้อยู่

นี่คือขอบที่รู้จัก เขียนไว้ตรง ๆ ไม่ได้ซ่อน

- ในเทมเพลต ตัวอักษร `1` `a` `A` `i` `I` `ก` `๑` เป็น placeholder ดังนั้นคำปกติที่มีตัวอักษรเหล่านี้อยู่จะถูกแปลงเป็นตัวนับ ให้สร้างคำนำหน้าจากตัวอักษรนอกชุดนี้ หรือเขียนแบบ `ข้อ ๑.` ที่มีแค่เลขไทยเป็น placeholder ส่วน `ข้อ ` เป็นข้อความจริง
- `formats` ใน frontmatter อ่านได้ทั้งแบบ block list และ flow list บรรทัดเดียว
- รายการข้อความล้วนเยื้องได้เฉพาะเมื่อมีรายการก่อนหน้าในชั้นเดียวกันให้ย้ายไปอยู่ใต้ กฎเดียวกับที่ Word ใช้
- ถ้าข้ามระดับ heading ช่องที่ขาดจะถูกเติมด้วย `1` ดังนั้น `#` ตามด้วย `###` จะได้ `1` แล้ว `1.1.1`
- rich clipboard เขียน `text/plain`, `text/html` และ `text/rtf` แอปที่ไม่อ่านสักอย่างยังได้ข้อความล้วนพร้อมเลขครบ
